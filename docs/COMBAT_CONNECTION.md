# Optional Combat Tool connection

World Builder and DnDGameTool remain independent applications. Run both APIs only when you want to exchange data. Start World Builder normally; its existing FastAPI app now exposes `/integrations/combat` routes. In the combat app's **Admin** sidebar page, find **World Builder connection**. Its enable switch saves automatically; edit and save the API URL (normally `http://localhost:8000`) and browser URL (normally `http://localhost:5173`). Restart both updated APIs and refresh both frontends first.

In a campaign's Story Planner, edit a plot point and use **Attach combat encounter**. Prepare a roster using world PCs/NPCs or generic named combatants, with allegiance, quantity, optional HP/AC/level, location and a battle-map image. Saving preserves the plot point's existing story content and ID. **Open in Combat Tool** opens its import page; the combat app URL is configurable and defaults to `http://localhost:1212`. Loading campaigns selects that plot point, and a reviewed import creates/updates its combat scene. Characters can be linked to already entered combat units. Existing combat HP/statistics remain under the combat app's control.

Battle-map image bytes can be copied from this repo's `frontend/public` directory, the selected world's directory, or embedded base64 raster images. PNG/JPEG/WebP/GIF are supported up to 10 MB. An external image URL needs a local copy before sharing. Schematic canvases, markers and map drawings remain here. NPC references, including DM secrets, are saved privately in the combat app for offline use; refreshing is explicit and does not alter combat statistics.

The combat app's **Review encounter results** dialog sends an explicitly reviewed summary, optional outcomes and session number. This app appends one `story.combat_results` entry and a linked player action visible in campaign/session history. The player action remains unreviewed for story consequences. Sending the same result ID and payload again is a no-op. A conflicting reuse is rejected. Existing NPC records, plot-point statuses and clocks are never automatically changed. Legacy `StoryContent` remains supported and is not replaced by a result import; campaigns with that legacy story need the Story Planner before receiving summaries.

Reload an already open campaign after sending results. A stale entity or entity-YAML save that drops newly imported history returns 409. The ordinary single-worker API serializes entity-editor writes with result appends. Full YAML repair/backup restoration remains an explicit administrative operation. Existing YAML fields are retained when appending a result, and the existing YAML service backs up the source first. The integration adds optional fields; no authored world data is migrated on startup.

Exchange endpoints: `GET /integrations/combat/catalog`, `GET /integrations/combat/characters/{entity_id}`, `GET /integrations/combat/maps/{map_id}/image`, `POST /integrations/combat/results`. These are intended for the existing trusted local DM applications, with no added authentication or public player feed.
